# The player

Purpose: a player for music you already have on a server. It is a **Tauri 2** application —
Rust core, the operating system's own WebView, no bundled Chromium and no Electron — that
speaks **Subsonic / OpenSubsonic** to whatever server a person points it at. It is a client
and only a client: it never runs this app's Python backend, it ships no acquisition code, and
it does not need the desktop host in `desktop/`. The shells are separately distributable and
share only the stylesheet: `player/ui/src/app.css` imports `web/styles/app.css` at build time,
so a visual change belongs in `web/styles/` and never in the player.

Card: **PLAYER-001** — the shell and its connect screen. Everything past the handshake has a
card of its own, listed at the end.

> **Current build (2026-11-14).** The player is `player/ui/`: Svelte 5 + TypeScript + Vite,
> built to `player/ui/dist`, and `tauri.conf.json` points at it. It talks to the server through
> the typed Subsonic client in `player/ui/src/lib/subsonic/`; it does not load `web/index.html`
> and it names none of this server's `/api/…` routes except the two social reads described below.
> The earlier host-shell approach — an
> `assemble.mjs` that copied `web/` into a gitignored `player/www/`, a `player/shell/` of
> classic scripts, and an offline-download feature — is **deleted**, not merely unused. `P4` in
> the plan removed it after `tauri.conf.json` stopped pointing at it.

## Layout

```
player/
  ui/                   THE PLAYER. Svelte 5 + TS + Vite; `npm run build` writes ui/dist
    index.html          the Vite entry document
    src/app.css         imports ../../../web/styles/app.css: the app's own visual language
    src/lib/subsonic/   typed Subsonic client: auth, transport, normalize, errors, capabilities
    src/lib/library/    the library store: albums, artists, playlists, search, lazy pages
    src/lib/player/     the playback store, the engine seam (web + native), select, waveform
    src/lib/app/        the session: one active server, native transport first, fetch fallback
    src/lib/accounts/   the vault seam: secrets go to Rust, never to the page
    src/lib/hardly/     the one non-Subsonic surface: the social capability probe, inert
    src/components/     Connect, Shell, TrackList, AlbumCard, Cover, CompactPlayer, FullPlayer,
                        QueuePanel, Subtitle, LyricsOverlay
    tools/parity.cjs    proves these surfaces against tests/visual/baseline/
  src-tauri/
    Cargo.toml          tauri 2, one library crate for desktop/iOS/Android
    build.rs            tauri_build
    tauri.conf.json     the window, ../ui/dist as the front end, desktop + iOS + Android bundle
    capabilities/default.json   core permissions only: no fs, shell or HTTP plugin
    src/lib.rs          the builder, the managed state, every command
    src/main.rs         the desktop binary
    src/accounts.rs      the keychain, or an in-memory vault that says so
    src/subsonic.rs      the commands that know the address and the credential
    src/subsonic_url.rs  pure: origin pinning, endpoint/param checks, the token
    src/native_audio.rs  the native-audio commands (no platform player compiled in yet)
    src/native_queue.rs  pure: the order, the advance rules, the event shapes
```

`player/ui/dist` is generated by Vite and is the only thing the window loads. There is no
second tree.

## What the player contains, and what it must not

The player's contents are a property of the **build**, and `tests/test_player_store_safe.py`
asserts them over `player/ui/dist` — the tree the window actually loads — rather than over a
list in a script, because a list is a promise and a build is evidence. See
[player/store-safe.md](player/store-safe.md).

Present, because a client needs them: the Subsonic client (auth, transport, normalisation,
error codes), the library surfaces (albums, artists, playlists, search, stars), playback and
Up Next, lyrics, and optionally this server's social feed once PLAYER-006 lands.

Absent, by construction: **every `/api/…` route this server registers**. A player that spoke
them would be a second client of one implementation; it speaks `/rest/…` instead. Also absent:
the acquisition module, the download queue, source matching, the offline cache, and the
provider browser. None of these is hidden behind a flag — the modules do not exist.

Two consequences worth stating plainly:

* **The exclusion is checked, not remembered.** The test derives the forbidden names from
  `api/v1.py`'s own route table and from `web/js/repo-discovery.js` at test time, so a new
  server route joins the assertion without anyone updating a list. It has a negative control:
  it plants a private route and a machinery token in a copy of the build and requires the audit
  to report them.
* **It cannot prove a runtime-built URL.** A player script could concatenate a route at
  runtime and no static audit would see it. That limit is stated in `store-safe.md` rather than
  left implied.

## Running it

Requirements beyond this repository: Rust (stable), the Tauri 2 CLI
(`cargo install tauri-cli --version "^2"`), and the WebView development packages for the
platform — on Linux `webkit2gtk-4.1`, `gtk+-3.0` and `libsoup-3.0`, per Tauri's prerequisites
page.

```sh
# the player's own build (also run by Tauri's beforeBuildCommand)
cd player/ui && npm install && npm run build

# development: the Vite dev server starts first, then the window opens
cd player/src-tauri
cargo tauri dev

# a desktop build (appimage/deb on Linux, .app on macOS, .msi on Windows)
cargo tauri build
```

`beforeDevCommand`/`beforeBuildCommand` in `tauri.conf.json` call `npm --prefix ui run dev` /
`run build`, so the front end is not a step a person can forget (Tauri runs them from
`player/`). To look at the player without Rust, `cd player/ui && npm run dev` and open
`http://localhost:5179`; `?preview=compact|fullscreen|queue` renders one surface on its own for
the parity harness, and `node tools/parity.cjs` grades all of them against the stored
baselines.

`vite.config.ts` sets `base: "./"` because the shell serves `dist/` over Tauri's asset
protocol — there is no server to resolve an absolute path, on any of the three platforms.

`security.csp` is set (2026-11-17), one policy for all three platforms:

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data: blob: http: https:; media-src 'self' data: blob: http: https:;
connect-src 'self' ipc: http://ipc.localhost; font-src 'self' data:;
object-src 'none'; frame-src 'none'; base-uri 'none'; form-action 'none'
```

Each allowance has a reason, and the reasons are why the policy is not tighter:

- **`img-src`/`media-src` need `http:`/`https:`.** A cover and a stream are URLs the native side
  hands to an `<img>` and an `<audio>` element. A media element cannot carry headers, so its
  authentication travels in the query string and the page itself must be allowed to fetch the
  URL. The host is the account's own server, but a policy cannot name a host a person types.
- **`style-src` needs `'unsafe-inline'`, for attributes only.** Sheets are one bundled file, but
  several components set `style=` (the queue slot's position, the record's travel, the volume's
  `--vol`). `style-src-attr` would say this more precisely; it is ignored by WebKit before 15.4,
  which would then block those attributes outright, so the older spelling stays.
- **`script-src 'self'`, with no `'unsafe-inline'`.** That is the point of the policy: the page
  runs the bundle and nothing a server, a cover or a lyric could smuggle in.
- **`connect-src` stays at the asset origin and IPC.** The page names endpoints and never URLs;
  Rust resolves the host and the credential. The two reads outside `/rest` — the capability
  document and the feed — go through the native side for the same reason
  (`lib/hardly/native.ts` → `subsonic_public`, `docs/player/social.md`), which is what keeps this
  policy at IPC instead of widening it to `http: https:`. The only page-side `fetch` left is the
  no-native fallback in `transport.ts`, which exists for shells older than the native transport
  and is refused here by design.

Measured on the Linux build against a stub OpenSubsonic server: connect, album wall with real
covers and the drawn fallback, artists, playlists, playlist detail, artist detail, album detail,
a row's queue action, and the full player (record, label artwork, seek, volume) all render with
no CSP refusal in the app log. `media-src` was not exercised — no playback was run on the
workstation — so a stream under this policy is unproven until it plays on the device. The policy
is baked into the packaged binary: the string is present in the arm64 IPA's executable, so the
shipped app carries it rather than the source only.

### iOS and Android

Tauri generates the platform projects; they are **not** committed (`gen/apple`,
`gen/android` are gitignored, and `src-tauri/gen/` is what the CLI produces):

```sh
cd player/src-tauri
cargo tauri icon path/to/1024.png     # icons are not in the tree yet
cargo tauri ios init                  # once: writes gen/apple
cargo tauri android init              # once: writes gen/android
cargo tauri ios dev                   # or: cargo tauri android dev
```

`bundle.iOS.minimumSystemVersion` is 13.0 and `bundle.android.minSdkVersion` is 24; those are
declared in `tauri.conf.json` and unverified here (see below). The window URL is `index.html`,
the same relative page on all three platforms, so no platform gets its own front end.

## The connect screen

When no server is configured the window shows one card: server address, username, password
(`src/components/Connect.svelte`). It calls
`<server>/rest/ping.view?u=…&p=…&v=1.16.1&c=hardlylistening-player&f=json` and reads the reply
as the protocol defines it:

* a **`subsonic-response` with `status: "ok"`** is a success, and the screen reports the
  server's `type`, `serverVersion` and whether it is `openSubsonic`;
* an **`error` object** is reported by its code — 40 is wrong credentials, 30 is a protocol
  version the server will not speak, 10 a missing parameter — with the server's own message
  appended when it adds something;
* **anything else** (an HTML login page, a proxy error, JSON without the envelope) is refused
  as "answered, but not as a Subsonic server", because a person needs to know which of those
  happened.

The address is normalised only where normalising cannot be wrong: trailing slashes are
dropped, and a pasted `/rest` suffix is named rather than doubled. A missing scheme is
refused rather than guessed (`http` versus `https` is the person's choice).

**Credentials go to the OS keychain** (`src-tauri/src/accounts.rs`: Keychain, Credential
Manager, Secret Service). A platform with no keychain backend keeps the secret in memory and
says so, rather than writing a password to disk. The page holds an account's public record —
id, address, username, label — and asks Rust for the secret when a request needs it. The
password crosses to the server as Subsonic's plain `p=` parameter, so the address should be
`https://`; token auth (`t`/`s`, md5) is supported by the client but not used for the bind.
`docs/player/accounts.md` and `docs/player/transport.md` are the two documents for this.

## What is unverified, and why

This machine is Bazzite (immutable) with **no `webkit2gtk-4.1`, `gtk+-3.0` or `libsoup-3.0`
development packages and no `cargo-tauri`**, so the Rust crate and the Tauri configuration
have not been compiled, and no window has been opened. `cargo check` stops at `glib-sys`. What
is proven here is what can be proven without them:

* the JSON files parse and describe the shapes Tauri 2 reads;
* `rustfmt --check` accepts the `.rs` files, and the two pure modules (`subsonic_url.rs`,
  `native_queue.rs`) are compiled and exercised in throwaway crates;
* the front end builds (`vite build`), type-checks (`svelte-check`), and its unit tests pass;
* the build's surfaces are graded against the app's stored screenshots by `tools/parity.cjs`;
* the built tree is audited file by file by `tests/test_player_store_safe.py`.

`subsonic.rs` and `native_audio.rs` — the command layers — have **never been compiled**.
Compilation, `gen/apple`/`gen/android` generation, a real WebView, and the platform audio
engine therefore need a machine with the WebView packages, or a macOS runner plus the Android
SDK.

One gap that only a real build will settle: iOS ATS needs an exception before a plain `http://`
LAN server answers. The CORS gap this paragraph used to describe is closed — the `subsonic_*`
commands send the request from Rust, so the server's origin policy stops mattering, and the
secret never returns to the page. The one value that still crosses is a stream URL; see
`docs/player/transport.md`.

## Compatibility

`player/ui/src/lib/subsonic/compat.test.ts` runs one suite over recordings of two real servers —
Navidrome 0.64.2 and Supysonic 0.8.0 — captured by `tools/record-compat.mjs` (status, content
type and raw body, nothing retyped). What they disagree about, and what the client does with it,
is in [player/compat.md](player/compat.md).

## Social, when the server has it

The feed is this app's own feature, not the protocol's, so `player/ui/src/lib/hardly/social.ts`
asks the server's capability document whether it exists at all: `GET /api/v1/capabilities`, a
named `features.social.activity`, and no required member session. The answer is one of four
states — `activity`, `members`, `no-activity`, `absent` — and every failure lands in `absent`
with a reason rather than as an empty feed. `Session.social()` is the seam; nothing draws a feed
yet, and the probe is inert. The states, the read's typed refusals and the store-safe exception
are in [player/social.md](player/social.md).
